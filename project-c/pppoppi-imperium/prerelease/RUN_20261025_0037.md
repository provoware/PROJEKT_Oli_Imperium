## Sicherheitsproblem, Abhaengigkeiten, erwartete Wirkung

Bisher loeschte der Importer bei einem Fehler `shutil.rmtree(destination)`. Wurde der sichtbare Zielpfad inzwischen auf einen anderen Ordner umgelenkt, konnte der Loeschvorgang fremde Dateien betreffen. Auch die Installations-`rename`-Aufrufe nutzten den veraenderlichen Pfad.

**Umsetzung:** Zwei Umbenennungen erfolgen relativ zum geoeffneten, mit `O_NOFOLLOW | O_DIRECTORY` geschuetzten Zielverzeichnis. Der Import kontrolliert die Dateiidentitaet dieses Verzeichnisses vor und nach der abschliessenden Validierung. Fehlt die sichere POSIX-Unterstuetzung, wird die Installation abgelehnt. Bei Schreibfehlern wird kein Zielpfad mehr rekursiv geloescht: Ein unvollstaendiger Import bleibt zur sicheren manuellen Untersuchung erhalten und gilt ausdruecklich als fehlgeschlagen.

**Regressionen:** Bestehender simulierter zweiter Schreibfehler wurde auf nicht-destruktive Semantik umgestellt; neue Tests tauschen das Ziel nach dem ersten Schreibschritt gegen einen Symlink auf ein fremdes Verzeichnis und pruefen sowohl einen formal vollendeten Schreibvorgang als auch einen anschliessenden Schreibfehler. Fremde Markierungsdateien duerfen nie verschwinden oder ueberschrieben werden.
