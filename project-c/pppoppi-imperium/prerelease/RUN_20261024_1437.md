## Warum dieses Paket priorisiert wurde

Alle 49 technischen Vorrelease-Pflichten koennen ohne den gesicherten Spielkern nicht
vollstaendig geprueft werden. Ein weiterer reiner Sicherheits-Feintest des
Pruefers beseitigt diese Hauptblockade nicht. Der neue **Offline-Importhelfer**
verringert die praktische Huerde, das bereits vorhandene, aber noch nicht auf
GitHub gespeicherte Spielpaket reproduzierbar nachzuimportieren.

## Tatsaechlich implementiert

1. 'recovery/import_archive.py' akzeptiert nur zwei **fest kryptografisch
   gebundene** ZIP-Varianten: das Originalpaket mit 187 Eintraegen oder das
   medienbereinigte Quellpaket. Beliebige fremde ZIPs werden abgewiesen.
2. Beim Original werden ausschliesslich Quell-/Test-/Textdateien unter
   'SPIEL/' ausgewaehlt; 77 Medien-/Berichtseintraege bleiben draussen.
   Die Dateiliste und alle SHA-256-Werte muessen dem fest verankerten
   110-Dateien-Inventar entsprechen. Das Manifest wird daraus erzeugt.
3. Beim kuratierten ZIP werden die enthaltenen 110 Dateien und das Manifest
   ebenfalls gegen die feste Inventarbindung geprueft.
4. ZIP-Pfadmanipulation, symbolische Links, doppelte Namen, Sonderdateien,
   ungueltige oder uebergrosse Eintraege und unvollstaendige Entpackvorgaenge
   werden abgefangen. Ein offenes Archiv wird vor und nach dem Entpacken
   gegen denselben festen SHA-256-Wert geprueft.
5. Erst nach allen Pruefungen wird ein **neuer** Zielordner exklusiv angelegt.
   Existierende Ziele werden nie ueberschrieben. Bei einem Installationsfehler
   wird ausschliesslich der neu angelegte Zielordner zurueckgenommen.
6. Zwei CI-Workflows pruefen jetzt alle 'test_*.py' der Recovery-Schicht.
   14 neue synthetische Regressionen; insgesamt 42 Recovery-Tests.
